# GlacierEQ Recruiter Runtime Portfolio

**One evidence graph. Four presentations. No claim drift.**

[Open the live portfolio](https://casey-barton-glaciereq.vercel.app)

GlacierEQ’s public hiring surface is a deployed portfolio system for four different evaluators:

| Route | Audience | Purpose |
|---|---|---|
| [`/resume/`](https://casey-barton-glaciereq.vercel.app/resume/) | Recruiters and ATS workflows | Direct professional identity, experience, skills, and selected proof |
| [`/frontier-laws/`](https://casey-barton-glaciereq.vercel.app/frontier-laws/) | Recruiters, founders, and hiring managers | AI operating bottlenecks, laws, remedies, Infinity Stones, and Crown Jewels |
| [`/master-atlas/`](https://casey-barton-glaciereq.vercel.app/master-atlas/) | Senior engineers and technical leaders | Systems grouped by functional role and strategic company alignment |
| [`/machine/`](https://casey-barton-glaciereq.vercel.app/machine/) | AI systems and automated reviewers | Canonical graph, schemas, ProtoJSON, real Protocol Buffers, evidence classes, and authority boundaries |

The raw public repository catalog remains available at [`/repositories/`](https://casey-barton-glaciereq.vercel.app/repositories/), but the primary experience presents systems, operating laws, and evidence before exposing inventory.

## The Portfolio Interprets the Work

*Decision-maker lens · what changes for the evaluator*

A flat repository list makes the reviewer reconstruct the candidate’s architecture alone. This project instead:

- identifies the strongest systems and their functional roles;
- separates Crown Jewels, Infinity Stones, company-aligned exhibits, private architecture references, and raw inventory;
- explains the problem, operating law, implementation, proof, measured boundary, and next promotion target;
- preserves direct links to canonical source;
- gives every audience an appropriate amount of detail without changing the underlying facts.

The live presentation includes:

- frontier bottlenecks and operating laws;
- AKOS, Tower of Babel, PSYSOC-X, Job Application Helix, Resume Shapeshifter, Anthropic coordination, xAI infrastructure, ECHO/Sigma evolution, and private architecture boundaries;
- company-alignment views that expressly disclaim affiliation, endorsement, proprietary access, and production impact;
- a stable machine startup surface with exact authority and evidence limits.

### Production behavior

The deployed surface provides:

- static human routes with mobile-safe navigation;
- live public GitHub repository discovery;
- private-repository filtering;
- bounded pagination and partial-success semantics;
- repository detail and README inspection;
- runtime health and portfolio APIs;
- JSON, ProtoJSON, `.proto`, and binary `.pb` contracts;
- security headers and no third-party advertising or analytics scripts;
- checksum-gated archive and Protobuf deployment builds.

### Failure semantics

- Page 1 of repository discovery is required; later pages are bounded enrichment.
- Partial coverage is reported rather than converted into total failure.
- Invalid repository names fail closed.
- Private repositories are never returned by the public repository API.
- GitHub availability does not grant credentials, provider scope, private access, or execution authority.
- A machine bootstrap describes the presentation contract; it does not grant tools or permission.

## Evidence and Nonclaims

This repository and live site demonstrate public presentation engineering, evidence architecture, machine contracts, deployment verification, and repository intelligence.

They do **not** establish:

- employment by or affiliation with a named company;
- unrestricted production scale, customers, revenue, or business impact;
- private repository implementation details;
- current passing CI for every connected repository;
- production readiness for a child system merely because it is presented here;
- authority for an AI system to use tools, credentials, memory, or provider scope.
