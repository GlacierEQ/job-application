# Recruiter Package Hardening — July 30, 2026

This document binds the public `job-application` portal to the hardened recruiter package without placing private contact data or application operations into the public repository.

## Recruiter reading order

1. `RESUME.md` — durable resume entrypoint.
2. `SHOWCASE.md` — concentrated flagship evidence review.
3. `portfolio_manifest.json` — canonical recruiter-facing source of truth.
4. `job-app-helix/hire_package/casey-barton` — role-targeted candidate surface, evidence ledger, claim register, and machine contracts.
5. `the-tower-of-babel` — governed technology placement, interoperability, proof classes, and explicit blockers.

## Package architecture

The complete package is deliberately multi-surface:

- PDF for fixed recruiter presentation;
- DOCX for editable human review;
- Markdown and plain text for ATS-safe ingestion;
- HTML for an offline guided portal;
- JSON, JSON-LD, YAML, CSV, and Mermaid for structured interoperability.

The package opens with the executive resume and recruiter decision brief, then exposes three README depths:

1. recruiter value and role fit;
2. senior-engineer architecture, invariants, and failure behavior;
3. AI/ATS entrypoints, typed relationships, and non-inference rules.

## Tower of Babel integration

Tower is not used as decorative language counting. It acts as the technology-authority layer: each technology has a defined responsibility, activation condition, interface boundary, proof class, and exact blocker when portable verification is unavailable.

The package binds to Tower main commit `1028a58986be6bedd1d8d09a63593876aab52d1d`, which exposes 30 governed technology floors, 60 linked exhibits, and the Advanced Exhibit Atlas.

## Evidence boundary

This integration does not convert repository source into deployment proof. Verified, candidate, blocked, unverified, and failed states remain distinct. Portfolio-wide deployment, scale, performance, reliability, and customer-impact claims require separate receipts.
