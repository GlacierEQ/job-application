# Anthropic — Reliable Agents Pitch

## Draft

I build agent systems that preserve context, separate sources of truth, and make complex work more reliable.

My recent work combines persistent memory, tool and connector integration, auditable routing, deployment automation, and operator-facing documentation. The architecture uses GitHub for durable source, Supabase for identity and relational state, Vercel for deployment, Supermemory for persistent model context, Notion and Drive for human-readable control surfaces, and Aspen Grove / M2A for model-to-agent routing and event traces.

Selected proof-of-work:

- `GlacierEQ/apex-stack`
- Aspen Grove memory architecture
- M2A / MCP-to-All routing work
- connector health and deployment runbooks
- multi-agent orchestration projects

The engineering principles behind this work are:

- keep canonical data separate from model memory
- make routing decisions inspectable
- suppress irrelevant or degraded responders
- preserve audit trails
- prefer clear interfaces over hidden coupling
- keep human control available
- treat reliability as an architectural property

I am interested in infrastructure, product engineering, developer tools, agent reliability, memory systems, evaluations, or platform roles where careful engineering judgment matters.

What I would bring:

- practical systems thinking
- TypeScript, Python, Node.js, and Bash
- agent memory and orchestration architecture
- API and connector integration
- deployment and CI automation
- concise technical documentation
- willingness to simplify systems instead of adding complexity for its own sake

I would welcome the opportunity to discuss the tradeoffs in the architecture, including what should remain deterministic, what belongs in model memory, how auditability is preserved, and how human operators stay in control.
